# PixelRunner "镜头与后期" 效果栈实施计划

日期：2026-07-30  
状态：提案，待评审后实施

## 1. 目标与产品定位

在工具箱新增一项 **镜头与后期**。它不是又一组一键滤镜，而是一个可排序、可开关、可保存为预设的非破坏性编辑会话：用户在插件内调整一条效果栈，只在点击“应用”时向 Photoshop 生成一个新的结果层。

产品层级约定：

- 工具箱卡片名称：`镜头与后期`。
- 弹窗标题：`后期效果台`。
- 编辑核心名称：`效果栈`。
- 现有“辉光”和“空间特效”继续保留独立入口；首发仅复用其算法与桥接模式，不迁移或删除既有流程。

该方案同时服务两类创作：

1. 自然镜头与电影质感：让 AI 返图、人物和旅拍更有镜头语言，但不破坏肤色与原图细节。
2. 风格实验：CCD、千禧梦核、像素化、CRT 和数字故障等可控风格化输出。

设计依据：小红书 2026 影像趋势强调胶片、生活感、氛围感、广角自拍、Live 图与自然色彩；同时 CCD 和中式梦核持续以“可控不完美”形成明确视觉识别。首发应提供可组合的底层机制，而非短周期网红滤镜名称。

参考资料：

- [OPPO x 小红书 2026 影像趋势报道](https://www.cphoto.com.cn/content/article/101280.html)
- [CCD 文化观察](https://www.36kr.com/p/3151857989680640)
- [中式梦核分析](https://36kr.com/p/3469501392198017)
- [Blender Glare Node](https://docs.blender.org/manual/es/3.4/compositing/types/filter/glare.html)
- [Blender Sun Beams Node](https://docs.blender.org/manual/es/3.5/compositing/types/filter/sun_beams.html)

## 2. 首发范围

### 2.1 八个原子效果

| ID | 名称 | 分类 | 算法和关键参数 | 首发原因 |
| --- | --- | --- | --- | --- |
| `lensDistortion` | 镜头畸变 | 自然镜头 | 径向反采样；桶形、枕形、鱼眼、中心点、缩放、边缘填充 | 支撑鱼眼、0.5x 广角边缘拉伸和 CRT 曲面 |
| `chromaticAberration` | 镜头色差 | 自然镜头 | RGB 通道沿径向以不同倍率采样；数量、半径、中心、色边方向 | 与辉光内部的高光色散区分，作用于整张图 |
| `vignette` | 暗角 | 自然镜头 | 椭圆距离遮罩；数量、中点、圆度、羽化、高光保护 | 低成本且可与多数镜头风格叠加 |
| `halation` | 胶片卤化 | 自然镜头 | 高亮阈值遮罩、线性空间多尺度模糊、暖红偏移、滤色或加色叠加 | 复用辉光的高光提取与模糊经验，能显著改善 AI 图的塑料感 |
| `grain` | 胶片颗粒 | 自然镜头 | 固定种子噪声、尺寸、粗糙度、单色/彩色、亮度调制 | 颗粒最后应用，保证尺寸不随预览缩放变化 |
| `pixelate` | 像素化 | 风格实验 | 降采样、最近邻放大、色阶限制、Bayer 抖动、像素锚点 | 输出“像素海报”，而不只是马赛克 |
| `crt` | CRT 显示器 | 风格实验 | 曲面畸变、扫描线、荫罩/RGB 像素格、磷光扩散、屏幕暗角 | 用于屏摄、游戏和二创，效果应保持克制可读 |
| `glitch` | 数字故障 | 风格实验 | 带种子的横向撕裂、区块错位、RGB 偏移、像素拉伸 | 固定种子保证预览、重开和导出可复现 |

### 2.2 首发预设

预设只能写入已定义的效果栈参数，绝不绕开渲染器另写一套效果。

| 预设 | 栈顺序 | 边界说明 |
| --- | --- | --- |
| 自然镜头 | 暗角 -> 低量颗粒 | 用作最轻的默认起点 |
| CCD 直闪质感 | 色差 -> 对比/色彩曲线 -> 轻微卤化 -> 颗粒 -> 暗角 | 不声称生成真实闪光投影，仅模拟成像质感 |
| 蓝调 Live | 色彩分级 -> 低量颗粒 -> 极弱暗角 | 待色彩分级节点进入首发或改为固定预设色彩变换；保留肤色保护 |
| 千禧梦核 | 色彩褪色 -> 软焦/卤化 -> VHS 故障模式 -> 颗粒 -> 边框可选 | VHS 是 `glitch` 的模式，不做不存在的视频 Datamosh 承诺 |
| CRT 夜屏 | CRT -> 低量辉光/卤化 -> 暗角 | CRT 内部先处理缩放和色彩，再叠扫描线与荫罩 |
| 像素海报 | 像素化 -> 可选色差/故障 | 面向海报、游戏和二创，不以“照片转像素画”为卖点 |

**首发新增一个内部色彩变换节点 `colorGrade`，但先不作为单独对外可添加的效果。** 它只供 CCD、蓝调 Live 和梦核预设使用，字段与渲染路径从第一天就按原子效果实现。这样不会让首发界面多出复杂的曲线、HSL 和 LUT 控件，也不会把色彩逻辑复制在每个预设里。

### 2.3 明确不在首发范围内

- 基于 AI 深度图的景深、焦点转移和人像抠图。没有可靠深度输入时，景深只会退化为普通模糊。
- Ghost Lens Flare、光束、光泄漏、去雾/加雾、外部 `.cube` LUT 导入。
- Kuwahara 油画化、边缘描线、JPEG 压缩仿真、真实 CRT 视频动态和 Datamosh。
- 跨文档合成、第二张素材输入、视频处理、时间轴和关键帧。
- 直接修改 Photoshop 原图层、自动覆盖上一次结果层或生成 Photoshop 原生智能滤镜。

这些效果均留在后续阶段，先验证首发渲染图、导出质量和预设工作流。

## 3. 关键产品决策

### 3.1 会话与输出

1. 点击“打开后期效果台”后，捕获一次来源图像并建立 `PostFxSession`。
2. 滑块、增删效果、重排效果只改变 WebView 会话，不写 Photoshop。
3. 点击“应用效果栈”后，从会话来源以原始像素尺寸重新渲染，放置一张命名为 `像素起子 后期 - <预设或自定义>` 的新图层。
4. 原图默认保持不动；不隐藏、不删除、不合并。若用户选择选区，结果只覆盖选区边界并保留透明区。
5. 关闭有未应用修改的面板时提示“保留草稿 / 放弃修改 / 继续编辑”。未应用草稿可本地恢复，但不应伪装成已经写入 Photoshop 的效果。

### 3.2 高分辨率是发布门槛

现有空间特效在 WebView 侧以 `CAPTURE_MAX_DIMENSION = 2200` 渲染最终结果。该策略适合局部特效预览，但不可静默复用于整图后期；大图会被缩小后回贴，导致清晰度损失。

首发后期效果台必须采用以下策略之一，实施前以技术验证决定：

1. **推荐：Host 端原尺寸分块渲染。** Host 从 Photoshop 以原尺寸、带重叠边界的 tile 读取像素，WebView/renderer 对每块处理并回传，Host 拼接为最终 PNG。重叠值为效果栈中最大采样半径，避免模糊、卤化和 CRT 荧罩的接缝。
2. **可接受备选：WebGL 原尺寸渲染。** 当可用纹理尺寸、内存和桥接载荷允许时，直接以原尺寸渲染；超过限制时自动转分块。

严禁把预览 JPEG 当最终输入，也严禁在超过能力上限时降分辨率后不告知用户。无法满足原尺寸输出时，“应用”必须禁用并显示可执行的原因和恢复路径。

### 3.3 颜色、顺序与边缘规则

- 所有会产生/扩散光能的节点，至少 `halation`、辉光复用和 CRT 的磷光扩散，在线性色彩空间计算：sRGB 解码 -> 节点计算 -> sRGB 编码。
- 效果栈顺序由上到下执行。推荐默认顺序为几何变换 -> 色彩/高光 -> 显示器/像素化 -> 颗粒/故障。
- 对几何节点和 CRT，统一提供边缘策略：`缩放填满`、`镜像延展`、`透明`；默认 `缩放填满`。
- 所有随机效果都有 `seed`；新建效果时生成一次，预览期间保持不变；用户可点击重掷种子。预设包含默认种子但新建预设实例会派生会话种子。
- 单个效果必须可以旁路、复制、删除和重排；删除效果需要可撤销，清空整个栈需要二次确认。

## 4. 交互与界面规划

### 4.1 工具箱卡片

在 `app.html` 的辉光和空间特效之后增加一张与其同等级的工具卡：

- 标题：`镜头与后期`
- 状态：当前预设或“自定义效果栈”
- 描述：实时预览镜头、胶片与风格化后期，确认后生成新结果层。
- 主按钮：`打开后期效果台`
- 授权状态：与现有受控工具一致，未授权时卡片和 Host 请求均不可绕过。

### 4.2 后期效果台

使用单个可关闭的模态工作台，保持当前 Glow/Space FX 的紧凑深色工具面板风格，而不是另建营销式页面。

桌面宽度布局：

```text
+--------------------+--------------------------------------+--------------------------+
| 分类/预设           | 预览视口                             | 效果栈                   |
| 自然镜头            | 原图 / 分屏 / 效果 三态切换          | 1. 每项：开关、名称、    |
| 风格实验室          | 缩放、平移、适应画布                 |    拖拽把手、删除        |
| 我的预设            | 点击光源或畸变中心时显示明确控制点   | 2. 当前节点展开参数      |
|                     |                                      | 添加效果菜单             |
+--------------------+--------------------------------------+--------------------------+
| 来源信息、预览分辨率、后端、耗时、警告             | 重置 | 保存预设 | 应用效果栈 |
+-----------------------------------------------------+--------------------------+
```

窄面板布局：预览在上，效果栈在下；预设分类作为横向标签或菜单，不能与 Photoshop 面板主滚动产生嵌套滚动冲突。控制栏始终可见，但不能遮住参数或预览。

### 4.3 操作细节和无障碍要求

- 首次打开先显示来源捕获状态；在捕获完成前，添加、应用和保存均为明确的禁用状态。
- 预览模式必须有文字标签：`原图`、`分屏`、`效果`，不能仅以颜色或图标区分。
- 预览的点击中心、平移、缩放均有按钮替代路径；拖拽重排必须有“上移/下移”键盘替代路径。
- 所有图标按钮提供 `title` 与 `aria-label`；Tab 顺序必须与视觉顺序一致；Escape 关闭面板并遵循草稿确认规则。
- 处理超过 300ms 时显示稳定尺寸的进度/忙碌状态；拖动参数使用约 90ms 防抖，并取消过时渲染任务。
- 焦点态、禁用态、错误态均不能只依赖颜色。文字对比度不低于 4.5:1，并尊重 `prefers-reduced-motion`。
- 应用前显示将生成的图层名称与原始输出尺寸；应用过程中禁用破坏会话一致性的操作，但保留取消或明确的“完成当前渲染后取消”状态。

### 5.2 `PostFxSession`

```js
{
  version: 1,
  sessionId: "postfx-...",
  documentId: 123,
  sourceLayerId: 456, // 0 表示以合成图为来源
  sourceKind: "document-composite" | "active-layer" | "selection",
  sourceBounds: { left, top, right, bottom },
  originalSize: { width, height },
  previewAsset: { dataUrl, width, height, mimeType },
  selectionMaskAsset: { dataUrl, width, height } | null,
  sourceRevision: { documentId, activeLayerId, boundsHash },
  captureAt: "ISO timestamp",
  stack: PostFxStack,
  view: { mode: "split", scale: 1, x: 0, y: 0 },
  preview: { jobId: 0, backend: "webgl2" | "cpu", status: "idle" },
  draft: { dirty: false, presetId: "" }
}
```

### 5.3 `PostFxStack`

```js
{
  version: 1,
  colorSpace: "srgb",
  items: [
    {
      instanceId: "fx-...",
      type: "vignette",
      enabled: true,
      opacity: 1,
      seed: 0,
      params: { /* effect-registry normalized */ }
    }
  ]
}
```

规则：`type`、`params` 和默认值只由 `effect-registry` 定义；预设、UI 和渲染器都不得各自猜测参数。未知节点保留原始 JSON 但标记为不可渲染，避免未来版本降级时静默丢失用户预设。

### 5.4 Host 端点和一致性校验

建议保持“捕获”和“应用”两个明确端点：

```text
photoshop.captureLicensedPostFxSession
photoshop.applyLicensedPostFxStack
```

捕获端点返回低分辨率预览资产、原始尺寸、文档/图层/选区信息与可复验的 `sourceRevision`。应用端点接收 `sessionId`、标准化 `PostFxStack`、`sourceRevision` 和输出策略；Host 在开始原尺寸处理前重新校验文档、图层、边界和选区。任何不一致都拒绝应用并要求重新捕获。

不要让 WebView 直接将一个完整大图的 `dataUrl` 回传为最终方案。现有桥接和 `captureDocumentPreview()` 适合预览捕获，但在高分辨率整图上会受到 JPEG、base64、WebView 内存与单次载荷限制。

## 6. 渲染设计

### 6.1 预览路径

1. Host 捕获最长边 1536px 的 JPEG/PNG 预览，不修改 Photoshop。
2. WebView 解码来源，按栈顺序执行效果。
3. 首选 WebGL2：每一节点是一个全屏 pass，两个 FBO ping-pong，避免每步 `readPixels`。
4. CPU Canvas fallback 仅保证畸变、暗角、颗粒、像素化和基础故障可用；卤化/CRT 在 CPU 回退上可降低预览分辨率或显示“高质量预览需要 WebGL2”。
5. 每次修改参数递增 `jobId`。旧作业即使完成也不得覆盖最新预览。

### 6.2 最终路径

1. 选择并实现原尺寸分块渲染验证方案。
2. 将每块的源坐标和扩展边界传入渲染器，节点在全局坐标中计算噪声、暗角、色差半径，保证 tile 间连续。
3. 每个 tile 的输出裁回核心区域，再由 Host 编码和放置。
4. 仅当所有 tile 成功后才向 Photoshop 新建结果层；失败时不留下半成品图层或临时文件。
5. 对处理时间较长的文档显示阶段进度：读取、渲染、第 N/M 块、编码、放置。

### 6.3 效果的正确实现约束

- `lensDistortion`：反向映射输出像素到来源 UV，避免前向写入空洞；UV 计算须做长宽比校正。
- `chromaticAberration`：为 R/G/B 分别采样。默认 G 保持中性，R/B 反向径向偏移；“RGB Split”只作为 `glitch` 的非物理模式，不能混用术语。
- `halation`：先以亮度阈值和 knee 生成遮罩，再多尺度模糊；颜色偏暖且受亮部保护控制。可抽取/迁移辉光的 source mask 与 pyramid blur，但不得复制一份独立版本。
- `grain` 和 `glitch`：采用基于 `globalPixelX/globalPixelY/seed` 的哈希噪声，不能以 tile 内局部坐标生成，否则会拼缝。
- `pixelate`：按输出像素网格固定采样中心；量化与抖动在同一颜色空间定义。缩放使用 nearest，不能受到浏览器双线性插值影响。
- `crt`：管线顺序为图像采样/几何 -> 可选色彩处理 -> scanline/shadow mask -> phosphor bloom/暗角。扫描线根据最终输出像素密度计算，避免预览和导出不同频率。
- `glitch`：允许“VHS 信号”“数字撕裂”“像素拉伸”三种模式；不宣称支持需要帧间运动数据的 Datamosh。

## 7. 分阶段实施

### 阶段 0：技术尖峰与基线（先做）

目标：在未开始 UI 大改前确认原尺寸输出可行、数据流可控。

1. 为一张 6000px 以上、含透明边缘的 PSD 建立测试夹具。
2. 做单节点暗角与卤化的原尺寸 tile prototype，验证边缘重叠、色彩空间、透明 alpha 和拼接无缝。
3. 比较 WebGL 原尺寸、WebGL tile、CPU tile 三个路径的最大尺寸、耗时、内存和桥接载荷。
4. 确定 `sourceKind` 首发是否仅支持“当前合成图”或同时支持活动图层/选区。推荐首发：`当前合成图` + `当前选区`，活动图层作为后续增强。
5. 完成后把实测阈值写入常量和诊断信息；未通过则暂停 UI 实现，不以 2200px 降采样替代。

验收：6000px 文档的四角、渐变、高光扩散和透明区域均无 tile 接缝，输出尺寸与来源一致。

### 阶段 1：数据层、授权与空工作台

1. 新建 registry、stack 和 preset 模块，完成参数标准化与 JSON 迁移。
2. 新增 `postFx` 授权功能、Host method 映射和防绕过测试。
3. 新增工具箱卡片、空模态、会话捕获、关闭草稿确认和状态反馈。
4. 建立 `PostFxSession`，实现来源校验与重新捕获。
5. 实现预览视口的原图/分屏/效果模式、平移、缩放和键盘替代控制。

验收：未授权不能从 WebView 或 Host 端点进入；切换文档、图层或选区后应用会安全失败；任何关闭动作不丢失已确认的用户选择。

### 阶段 2：WebGL 渲染框架与写实节点

1. 实现 ping-pong renderer、资源释放、取消过期任务和 CPU fallback 框架。
2. 实现镜头畸变、全局色差、暗角、胶片颗粒和内部色彩变换。
3. 抽取现有辉光所需的高光遮罩/多尺度模糊为共享接口，或定义清晰的依赖边界；实现卤化。
4. 实现“自然镜头”“CCD 直闪质感”“蓝调 Live”预设。

验收：同一会话相同参数的预览可稳定复现；WebGL 失败时可见、可理解地降级；卤化不会让皮肤和整块白色背景无差别泛红。

### 阶段 3：风格实验节点

1. 实现像素化的像素网格、量化和 Bayer 抖动。
2. 实现 CRT 的四部分管线，并在高 DPI 与普通 DPI 预览下核验比例。
3. 实现带 `seed` 的三种故障模式和“重掷种子”操作。
4. 实现“千禧梦核”“CRT 夜屏”“像素海报”预设。

验收：预览缩放不改变像素网格、扫描线或颗粒的逻辑尺寸；再次打开同一草稿得到相同故障结果；效果禁用、删除和重排的结果符合顺序定义。

### 阶段 4：原尺寸应用、预设与打磨

1. 接入阶段 0 选定的 Host 原尺寸 renderer，输出新 Photoshop 图层。
2. 实现选区透明遮罩与边缘策略，确保输出位置、尺寸和 alpha 正确。
3. 实现保存、覆盖、重命名、导入/导出本地预设 JSON；导入校验版本与未知节点。
4. 建立性能诊断：预览/最终分辨率、后端、pass 数、tile 数、总耗时、回退原因。
5. 完成桌面窄宽度、键盘操作、焦点态、缩放及长参数文本的视觉回归。

验收：应用成功只产生一张完整结果层；失败和取消不会污染文档；自定义预设在重新启动后仍正确还原。

## 8. 测试计划

### 自动化

- `effect-registry`：所有节点默认值、边界值、非法参数、schema 迁移和未知节点。
- `effect-stack`：添加、复制、排序、旁路、删除、预设展开、种子确定性。
- 渲染数学：sRGB/线性往返、径向畸变、边缘采样、色差方向、暗角范围、噪声全局坐标。
- tile：不同 tile 尺寸、重叠半径和图像尺寸的无缝拼接，对比单图渲染容差。
- 桥接：会话 revision 变化、错误文档、失效选区、取消、Host 端授权和超时。
- 授权：全功能许可证包含 `postFx`；旧许可证继续验证；仅有其他功能的许可证无法捕获和应用后期效果。
- 构建：新增模块进入 `app.bundle.js`，发布包完整且不引入网络依赖。

### 手工视觉矩阵

| 用例 | 必验结果 |
| --- | --- |
| 透明 PNG、半透明发丝 | 边缘不变黑、无暗边、alpha 正确 |
| 6000px 渐变天空和高光灯牌 | 无 tile 接缝；卤化连续；导出原尺寸 |
| 人像与白衣/高光皮肤 | CCD/卤化预设不大面积染红或过曝 |
| 建筑直线和广角画面 | 畸变方向、中心点、三种边缘策略正确 |
| 夜景霓虹 | 色差、CRT、辉光/卤化顺序正确且不闪烁 |
| 像素海报 | 像素格整齐；量化和抖动稳定；缩放不糊 |
| 三种 glitch | 相同种子一致；重掷种子仅改变随机节点 |

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 原尺寸像素在 WebView/桥接中占用过大 | 崩溃、超时、错误降分辨率 | 阶段 0 先验证 Host 分块；按 tile 处理，不传整图 data URL |
| WebGL2 兼容性 | 一部分环境没有高质量预览 | 明确 capability 检测、CPU fallback、降低预览分辨率，不改变最终质量承诺 |
| Canvas 在非线性 sRGB 中处理发光 | 卤化、辉光发灰/偏色 | 统一 `color.js` 的线性色彩约定与测试图 |
| 故障/颗粒 tile 拼缝 | 导出大图不可信 | 噪声使用全局坐标与会话 seed；专门做 tile 测试 |
| 预览和最终不一致 | 用户不信任效果 | 两条路径共享 registry、stack、shader/算法参数和固定 seed；记录 backend 差异 |
| 功能范围膨胀 | 交付拖慢、面板失焦 | 首发只承诺 8 个原子效果；阶段外节点必须重新评审 |
| 新授权功能影响旧激活码 | 已授权用户功能意外锁定 | 明确商业策略：发布前决定旧“全功能”许可证是否自动包含 `postFx`，并用签发/验证回归测试固化 |

## 10. 待产品确认项

实施前需要确认以下决策：

1. `postFx` 是单独授权功能，还是现有 `glow`/高级工具包的一部分？计划默认采用单独功能，便于发布和授权边界清晰。
2. 首发来源是“当前合成图 + 选区”，还是应直接支持“活动图层”？计划建议前者，以避免图层效果、智能对象、透明边界和上下文合成的复杂度同时进入首发。
3. 用户预设是否要支持 JSON 导入/导出？计划将其安排在阶段 4；若只需内置与本地保存，可先推迟导入/导出。
4. 第一版是否允许辅助色彩变换只由预设使用？计划建议是，这能保留蓝调/CCD/梦核风格，同时避免早期暴露复杂调色面板。
5. 是否把“广角边缘拉伸”明确列为镜头畸变的预设？计划建议是，但命名必须避免暗示会补出原图没有拍到的视野。

## 11. 完成定义

当且仅当满足以下条件，首发才可宣告完成：

1. 八个原子效果和六个预设均由同一效果栈、同一参数规范和同一随机种子机制驱动。
2. 预览在受支持设备上流畅更新，降级路径可理解且不假装高质量。
3. 最终输出保持来源的原始像素尺寸，并在大图、透明图和渐变图上没有可见拼缝。
4. 应用只生成一张完整的新 Photoshop 结果层，原图不被改写；取消或失败不产生文档污染。
5. 授权、会话失效、关闭草稿、键盘操作和窄面板布局均有测试覆盖。
6. 现有辉光、空间特效、融合校色和本地超分的入口、授权与构建测试均未回归。
